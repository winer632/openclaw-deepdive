架构全景

OpenClaw Gateway 的控制平面是一个单实例 WebSocket RPC 服务，监听 127.0.0.1:18789。 所有的管理操作——从会话管理到设备配对、从定时任务到语音唤醒——都通过这一个端口完成。

整个控制平面可以划分为 9 个功能层，涵盖 19 个独立的管理域：

设计哲学

一个端口统管一切。Gateway 不是微服务架构——它是一个精心设计的单体，通过方法命名空间（如 sessions.list、cron.add、device.pair.approve）在一个 WebSocket 连接上提供所有管理能力。

这种设计消除了服务间通信的复杂性，同时通过 Role + Scope 鉴权体系保证安全隔离。

通信协议

控制平面的所有通信都通过 WebSocket JSON 帧完成，遵循请求/响应模式，并支持服务端主动广播。

WebSocket 帧格式
Request（客户端 → 服务端） { method: "sessions.list",
  params: { limit: 20 },
  id: 1 }
Response（服务端 → 客户端） { id: 1,
  result: [...] }
// 或 error: { code, message }
Broadcast（服务端 → 全部客户端） { type: "presence",
  payload: {...},
  stateVersion: 42 }

每个方法通过命名空间约定组织：域.操作（如 config.patch）或 域.子域.操作（如 device.pair.approve）。 服务端通过 id 匹配请求和响应，客户端可以并发发送多个请求。

基础设施层

基础设施层提供整个 Gateway 运行所需的核心基座——配置存储、会话持久化、在线状态追踪、健康监控和密钥管理。

Config — 配置管理

config.* · 6 个方法

中心化配置存储，对应文件 ~/.openclaw/config.json5。定义整个系统的行为：agents、channels、models、secrets、gateway 端口等。

方法说明关键特性
config.get读取当前配置返回 JSON + hash，敏感值自动 redact
config.set替换整个配置需 baseHash 防写入冲突
config.apply写入配置并重启 Gateway写 restart sentinel → SIGUSR1
config.patch增量修改（JSON Patch RFC 6902）需 baseHash，支持部分更新
config.schema返回完整配置 schema含 UI 渲染提示，插件可扩展
config.schema.lookup按路径查询 schema 片段如 channels.discord.token
乐观并发控制

所有写操作必须携带 baseHash——读取时获得的配置哈希值。如果写入时 hash 已变（说明有并发修改），操作被拒绝。这避免了分布式锁的复杂性，用 Compare-and-Swap 语义保证一致性。

Sessions — 会话管理

sessions.* · 8 个方法

持久化的对话线程。每个 session 对应一个 JSONL 转录文件，session key 格式为 agentId@sessionId。

方法说明
sessions.list分页列出所有会话，支持按 agentId 过滤、排序
sessions.get获取单个会话完整元数据
sessions.resolve从部分标识符解析出完整 session key
sessions.preview批量获取消息预览（读取转录文件尾部 16KB）
sessions.patch更新元数据（model、thinkingLevel 等），需 baseHash
sessions.reset重置对话历史，归档旧转录并创建新 sessionId
sessions.delete删除会话及转录文件
sessions.compact压缩转录文件（合并消息，保留最近 N 条）

消息使用 parentId 链构成 DAG 结构（而非简单线性追加），支持分支对话。每个 session 携带丰富的元数据：model override、thinking level、subagent role（orchestrator / leaf）、exec 安全策略等。

Presence — 在线状态

system-presence · 3 个方法

实时追踪已连接的设备、节点和 Gateway 本身的状态。每个 presence 条目包含：host、ip、platform、deviceFamily、lastInputSeconds、mode（gateway/node）、roles、scopes 等。

  • TTL 5 分钟：过期条目自动清除
  • 版本号递增：每次变更 incrementPresenceVersion()，客户端可对比 stateVersion 判断是否需要刷新
  • 主动广播：通过 broadcastPresenceSnapshot() 推送给所有连接的客户端

Health — 健康监控

health / status · 2 个方法

health 返回完整健康快照：各 channel 状态、nodes、models、agents、plugins 的健康信息。缓存 15 秒，后台自动刷新。支持 probe=true 参数实时探测 channel 连通性。

status 返回摘要信息：host、version、内存用量、uptime、node 数量。admin scope 可见完整敏感字段。

Secrets — 密钥管理

secrets.* · 2 个方法

secrets.reload 从存储重载密钥运行时快照；secrets.resolve 按命令名和目标 ID 解析密钥分配关系。支持多种密钥源：环境变量、文件、1Password、Vault。

运行时层

调度层

Cron — 定时任务

cron.* / wake · 8 个方法

可调度的定时作业，自动触发 Agent 对话或系统事件。持久化存储在 ~/.openclaw/cron/jobs（每个 job 一个文件）+ ~/.openclaw/cron/runs（JSONL 日志）。

方法说明
cron.list分页列出定时任务，支持 query / enabled 过滤
cron.status获取 cron 服务状态（运行中的 job、队列统计）
cron.add创建定时任务
cron.update修改任务
cron.remove删除任务
cron.run手动立即执行任务
cron.runs查看执行历史日志
wake全局唤醒，触发立即执行 cron

三种调度模式：

at

指定时间点一次性执行。如 "2026-12-25T10:00:00Z"，执行后可自动删除（deleteAfterRun）。

every

按毫秒间隔循环执行。如每 30 分钟执行一次摘要。

cron

标准 cron 表达式，如 "0 9 * * *"（每天早上 9 点）。支持时区配置。

Payload 类型：agentTurn（发消息给 Agent）或 systemEvent（触发系统事件）。
结果投递：none / announce（推送到 channel）/ webhook（HTTP 回调，含 SSRF 防护 + 10s 超时）。

设备与节点层

这一层管理 Gateway 与外部实体（移动设备、远程计算节点）的认证和通信。

移动端 / 远程设备的注册与认证，用于 macOS / iOS / Android 原生 app 连接 Gateway。

慢客户端保护

广播时检测每个连接的 bufferedAmount。当缓冲区超过 MAX_BUFFERED_BYTES 阈值时，直接 socket.close() 断开慢客户端，防止一个慢客户端拖垮整个广播管道。

横切关注点

以下机制贯穿所有管理域，是控制平面的"基础设施的基础设施"。

Role + Scope 鉴权

三种角色：operator / node / device。权限通过 scopes 细分：operator.admin（super-scope）、operator.approvals、operator.pairing、operator.talk.secrets 等。

幂等性

Dedupe Map 存储 runId → {ts, ok, payload, error}，TTL 10 分钟。相同 runId 的重复请求直接返回缓存结果，不会重复执行 Agent turn。

乐观并发

Config 和 Session 的写操作需要 baseHash（Compare-and-Swap 语义）。避免分布式锁，设备/节点存储用 async lock 保护。

限流

Auth 尝试按 IP / role 限流。回环地址（127.0.0.1）豁免。config.apply、update.run 等写方法限 3 次 / 60 秒。

参数校验

AJV + TypeBox schema，每个方法入口自动校验。Protocol schema 定义在 gateway/protocol/schema/ 目录。

多级缓存

Health 快照 15s、channels.status 10s、usage.cost 30s、model catalog 运行时缓存。后台自动刷新，避免热路径重复计算。

优雅重启

写入 restart sentinel 文件 → 发送 SIGUSR1 → Gateway 进程优雅重启。用于配置热加载和版本更新。

慢客户端保护

广播时检测 bufferedAmount > MAX_BUFFERED_BYTES，超限直接 socket.close()。防止一个慢客户端阻塞整个事件管道。

TypeScript server.impl.ts — Gateway 启动流程概览 
// Gateway 启动的 10 个关键步骤（简化）
async function startGateway(options: GatewayOptions) {
  // 1. 加载配置快照（含 legacy 迁移）
  const config = await loadConfigSnapshot();

  // 2. 创建 auth 限流器（loopback 豁免）
  const rateLimiters = createAuthRateLimiters();

  // 3. 初始化运行时状态
  const state = {
    healthCache: createRefreshableCache(15_000),
    presenceVersion: 0,
    chatAbortControllers: new Map(),
    dedupeEntries: new Map(),       // 幂等性缓存
    wizardSessions: new Map(),
  };

  // 4. 创建请求上下文
  const context: GatewayRequestContext = {
    cronService: new CronService(jobStorage),
    execApprovalManager: new ExecApprovalManager(),
    nodeRegistry: new NodeRegistry(),
    channelManager: new ChannelManager(),
    broadcast: scopeGuardedBroadcast,
  };

  // 5. 注册所有 handler（29 个模块）
  registerHandlers(context);

  // 6. 启动 sidecar 服务
  await startChannelHealthMonitor();
  await startConfigReloader();
  await startBrowserControl();
  await startMaintenanceTimers();

  // 7. 监听 WebSocket 连接
  wss.on('connection', handleConnection);

  // 8. 绑定端口
  server.listen(18789, '127.0.0.1');
