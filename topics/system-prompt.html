System Prompt 组装与 Skill 注入

从 buildAgentSystemPrompt 到最终发送给 LLM 的完整提示词 — 一次拆解 OpenClaw 多段动态拼装机制

src/agents/system-prompt.ts 2026-03-13

总体架构

OpenClaw 的系统提示词不是一段静态文本，而是由 十余个独立段落（Section）在运行时动态拼装而成。核心入口是 buildAgentSystemPrompt() 函数（位于 src/agents/system-prompt.ts），它接收一个庞大的参数对象，根据运行时状态（渠道、工具、沙盒、子代理 vs 主代理等）有条件地生成最终提示词。

类比

可以把系统提示词想象成一份自助餐菜单：主菜（Identity + Tooling）永远在，但配菜（Skills、Memory、Reactions、Sandbox 等）根据"食客"（当前会话的渠道和角色）动态上桌。子代理（Subagent）只拿最简套餐，完整主代理则享用全席。

System Prompt 组装全景

委托
buildAgentSystemPrompt()
拼装 sections
lines.filter(Boolean).join("\n")

外层 buildEmbeddedSystemPrompt()（位于 src/agents/pi-embedded-runner/system-prompt.ts）负责收集运行时上下文（工具列表、工具摘要、沙盒信息等），然后交给核心的 buildAgentSystemPrompt() 进行实际拼装。最终结果通过 createSystemPromptOverride() 封装为一个闭包，注入到 AgentSession 中完全替换默认 prompt。

关键设计

Override 模式意味着 OpenClaw 完全接管 Pi Agent 的默认提示词，而不是追加。这使得 OpenClaw 可以精确控制 LLM 看到的每一个字节。

PromptMode 三级模式

系统提示词的信息量通过 PromptMode 类型控制，共三个级别：

模式 适用场景 包含的段落 典型 Token 开销
"full" 主代理（默认） 全部段落：Tooling, Safety, Skills, Memory, Messaging, Heartbeats, Silent Replies, CLI Reference, Self-Update, Model Aliases, Docs, Sandbox, Reply Tags, Voice, Reactions, Reasoning, Runtime, Project Context 3,000 ~ 8,000+
"minimal" Subagent / Cron 任务 Tooling, Workspace, Runtime；跳过 Skills, Memory, Messaging, Heartbeats, Silent Replies, Docs, Self-Update, Model Aliases, Reply Tags, Voice, Reactions 800 ~ 1,500
"none" 极简身份声明 仅返回 "You are a personal assistant running inside OpenClaw." ~15

export type PromptMode = "full" | "minimal" | "none";

}
// Memory section:

  if (params.isMinimal) return [];
  // ...

系统提示词的段落组装

buildAgentSystemPrompt() 内部按照固定顺序将各段落推入 lines[] 数组，最后用 lines.filter(Boolean).join("\n") 合并为字符串。每个段落由一个独立的 builder 函数生成，空数组表示该段落被跳过。

3 Tool Call Style 硬编码规则 永远包含
4 Safety 硬编码安全宪法 永远包含
5 CLI Quick Reference 硬编码 CLI 命令 永远包含

洞察

段落总数看似很多，但由于 PromptMode 和各种条件判断，实际生成的 prompt 远小于全量。例如，一个子代理（minimal 模式）的系统提示词可能只有 Identity + Tooling + Workspace + Runtime 四段。

Skill 三层加载策略

Skill 系统是 OpenClaw 的核心扩展机制。每个 Skill 是一个包含 SKILL.md 的目录，描述了 Skill 的能力和使用方法。Skill 的加载按三层优先级进行，由 src/agents/skills/workspace.ts 中的 loadSkillEntries() 函数实现。

Skill 三层加载优先级
Layer 1: Bundled Skills
skills/ (仓库内置)
优先级最低
Layer 2: User Skills
~/.openclaw/skills/
中等优先级
Layer 3: Workspace Skills
{cwd}/.openclaw/skills/
层级 来源目录 说明 可配置
Bundled skills/ (安装目录) OpenClaw 自带的基础技能，如 mintlify docs、commit 等 通过 skills.bundled.allowlist 过滤
User (Managed) ~/.openclaw/skills/ 用户全局安装的技能，通过 openclaw skills install 管理 通过 skills.filter 过滤
Workspace {workspaceDir}/.openclaw/skills/ 项目级别的技能，优先级最高，可覆盖同名技能 通过 skills.filter 过滤

此外还有 Plugin Skills：由已安装的插件（extensions）提供的技能目录，通过 resolvePluginSkillDirs() 发现。

Skill 注入到 Prompt 的过程

加载完毕后，Skill 并不将完整的 SKILL.md 内容注入到系统提示词中。而是生成一份紧凑的摘要列表，通过 formatSkillsForPrompt() 格式化后放入 <available_skills> 标签中。Agent 在收到用户消息时需要先扫描这个列表，如果某个 Skill 匹配，再用 read 工具读取完整的 SKILL.md。

TypeScript src/agents/system-prompt.ts — buildSkillsSection() 
function buildSkillsSection(params: {
  skillsPrompt?: string;
  readToolName: string;
}) {
  const trimmed = params.skillsPrompt?.trim();
  if (!trimmed) return [];
  return [
    "## Skills (mandatory)",
    "Before replying: scan <available_skills> <description> entries.",
    `- If exactly one skill clearly applies: read its SKILL.md at <location> with \`${params.readToolName}\`, then follow it.`,
    "- If multiple could apply: choose the most specific one, then read/follow it.",
    "- If none clearly apply: do not read any SKILL.md.",
    "Constraints: never read more than one skill up front; only read after selecting.",
    trimmed,  // <available_skills> XML block
    "",
  ];
}
关键设计: 延迟读取

系统提示词仅包含技能的名称和描述摘要（每个通常只有 1-2 行），而非完整的 SKILL.md 文件内容。这种 "scan first, read on demand" 模式在拥有 150 个技能时能节省数千 Token。

Token 优化：路径压缩

TypeScript src/agents/skills/workspace.ts — compactSkillPaths() 
// 用 ~ 替换 home 目录前缀，每个路径省 5-6 tokens
// 150 个 skills x 5 tokens = 750+ tokens saved
function compactSkillPaths(skills: Skill[]): Skill[] {
  const home = os.homedir();
  const prefix = home.endsWith(path.sep) ? home : home + path.sep;
  return skills.map((s) => ({
    ...s,
    filePath: s.filePath.startsWith(prefix)
      ? "~/" + s.filePath.slice(prefix.length)
      : s.filePath,
  }));
}

Bootstrap 上下文注入

Bootstrap 文件是在每次 Agent 运行前注入到系统提示词尾部 "Project Context" 段落中的上下文文件。它们为 Agent 提供项目特定的知识，如 AGENTS.md、SOUL.md、TOOLS.md 等。

Bootstrap 上下文加载流程
resolveBootstrapFilesForRun()
读取 & 过滤
buildBootstrapContextFiles()
截断 & 格式化
contextFiles[] -> "# Project Context"

流程详解：

  1. 发现阶段：loadWorkspaceBootstrapFiles() 扫描工作目录，收集 AGENTS.md、SOUL.md、TOOLS.md、HEARTBEAT.md 等标准文件
  2. 缓存：通过 getOrLoadBootstrapFiles() 按 session key 缓存，避免重复 I/O
  3. Session 过滤：filterBootstrapFilesForSession() 根据 session 类型决定包含哪些文件
  4. Hook 覆盖：applyBootstrapHookOverrides() 允许插件动态修改或注入额外的 bootstrap 文件
  5. 构建上下文：buildBootstrapContextFiles() 将文件内容按预算截断并格式化为 EmbeddedContextFile[]
TypeScript src/agents/bootstrap-files.ts 
export async function resolveBootstrapContextForRun(params: {
  workspaceDir: string;
  config?: OpenClawConfig;
  sessionKey?: string;
  sessionId?: string;
  // ...
}): Promise<{
  bootstrapFiles: WorkspaceBootstrapFile[];
  contextFiles: EmbeddedContextFile[];
}> {
  const bootstrapFiles = await resolveBootstrapFilesForRun(params);
  const contextFiles = buildBootstrapContextFiles(bootstrapFiles, {
    maxChars: resolveBootstrapMaxChars(params.config),
    totalMaxChars: resolveBootstrapTotalMaxChars(params.config),
    warn: params.warn,
  });
  return { bootstrapFiles, contextFiles };
}

ContextMode 上下文精简

Bootstrap 还支持 BootstrapContextMode（"full" / "lightweight"）。在 lightweight 模式下：

  • Heartbeat 运行只保留 HEARTBEAT.md
  • Cron / 默认 lightweight 完全跳过所有 bootstrap 文件

Token 预算与截断管理

Bootstrap 文件可能非常大（例如一个详细的 AGENTS.md 可能超过 10K 字符），因此需要严格的截断控制。这由 src/agents/bootstrap-budget.ts 实现。

预算参数 说明 默认值 配置路径
bootstrapMaxChars 单个文件最大字符数 由配置决定 agents.defaults.bootstrapMaxChars
bootstrapTotalMaxChars 所有文件合计最大字符数 由配置决定 agents.defaults.bootstrapTotalMaxChars
nearLimitRatio "接近上限"告警阈值 0.85 (85%) 硬编码

截断诊断系统

当 bootstrap 文件被截断时，系统会生成详细的诊断信息：

TypeScript src/agents/bootstrap-budget.ts 
export type BootstrapTruncationCause = "per-file-limit" | "total-limit";

// 截断文件分析结果
export type BootstrapAnalyzedFile = {
  name: string;
  path: string;
  missing: boolean;
  rawChars: number;       // 原始大小
  injectedChars: number;  // 实际注入大小
  truncated: boolean;     // 是否被截断
  nearLimit: boolean;     // 是否接近限制
  causes: BootstrapTruncationCause[];  // 截断原因
};

截断警告会通过签名机制（BootstrapPromptWarning）去重，支持三种模式：

  • "off"：不显示截断警告
  • "once"：相同签名只警告一次
  • "always"：每次都警告

被截断的内容会在系统提示词中显示为：

Text 系统提示词中的截断警告示例 
⚠ Bootstrap truncation warning:
- AGENTS.md: 12500 raw -> 8000 injected (~36% removed; max/file).
If unintentional, raise agents.defaults.bootstrapMaxChars
and/or agents.defaults.bootstrapTotalMaxChars.

渠道自适应 Prompt 构建

系统提示词并非对所有渠道一视同仁。不同的消息渠道（Telegram, Discord, Signal, Slack 等）会影响多个段落的内容。

渠道特性 影响的段落 具体表现
Inline Buttons Messaging Telegram 启用 inlineButtons 能力后，prompt 提示 Agent 可以使用 buttons 参数
Reactions Reactions Telegram/Signal 根据配置注入 minimal 或 extensive 反应引导
Message Tool Hints Messaging 渠道特定的 message 工具使用提示（如 Discord 线程创建规则）
Channel Capabilities Runtime Line capabilities=inlineButtons,reactions 写入 Runtime 信息
Reasoning Tags Reasoning Format 特定 provider（如某些推理模型）需要 <think>...</think> 标签格式
TypeScript src/agents/system-prompt.ts — buildMessagingSection() 
function buildMessagingSection(params: {
  isMinimal: boolean;
  availableTools: Set<string>;
  messageChannelOptions: string;
  inlineButtonsEnabled: boolean;
  runtimeChannel?: string;
  messageToolHints?: string[];
}) {
  if (params.isMinimal) return [];
  return [
    "## Messaging",
    "- Reply in current session -> automatically routes to the source channel",
    "- Cross-session messaging -> use sessions_send(sessionKey, message)",
    // ...
    params.availableTools.has("message")
      ? [
          "### message tool",
          "- Use `message` for proactive sends + channel actions.",
          params.inlineButtonsEnabled
            ? "- Inline buttons supported. Use action=send with buttons=..."
            : `- Inline buttons not enabled for ${params.runtimeChannel}.`,
          ...(params.messageToolHints ?? []),
        ].filter(Boolean).join("\n")
      : "",
    "",
  ];
}
洞察

Owner Identity 段落支持两种显示模式："raw"（原始手机号）和 "hash"（HMAC-SHA256 哈希后取前12字符）。Hash 模式使用 ownerDisplaySecret 作为 HMAC 密钥，防止 Agent 或日志泄露原始身份信息。

Runtime Line 与最终拼装

系统提示词的最后一段是 Runtime Line，它将当前运行环境的关键信息用 | 分隔压缩成一行：

TypeScript src/agents/system-prompt.ts — buildRuntimeLine() 
export function buildRuntimeLine(
  runtimeInfo?: { agentId?; host?; os?; arch?; node?; model?; defaultModel?; shell?; repoRoot? },
  runtimeChannel?: string,
  runtimeCapabilities: string[] = [],
  defaultThinkLevel?: ThinkLevel,
): string {
  return `Runtime: ${[
    runtimeInfo?.agentId ? `agent=${runtimeInfo.agentId}` : "",
    runtimeInfo?.host ? `host=${runtimeInfo.host}` : "",
    runtimeInfo?.repoRoot ? `repo=${runtimeInfo.repoRoot}` : "",
    runtimeInfo?.os ? `os=${runtimeInfo.os} (${runtimeInfo?.arch})` : "",
    runtimeInfo?.node ? `node=${runtimeInfo.node}` : "",
    runtimeInfo?.model ? `model=${runtimeInfo.model}` : "",
    runtimeChannel ? `channel=${runtimeChannel}` : "",
    runtimeChannel ? `capabilities=${runtimeCapabilities.join(",") || "none"}` : "",
    `thinking=${defaultThinkLevel ?? "off"}`,
  ].filter(Boolean).join(" | ")}`
}

最终拼装

所有段落通过一个统一的模式完成拼装：

TypeScript src/agents/system-prompt.ts — 结尾 
// 收集所有段落到 lines[] 数组
const lines = [
  "You are a personal assistant running inside OpenClaw.",
  "",
  "## Tooling",
  // ... 所有段落按顺序推入 ...
];

// 过滤空值，合并为最终字符串
return lines.filter(Boolean).join("\n");

full 模式（主代理）

  • 25 个段落全量加载
  • 包含完整 Skills 索引
  • Memory Recall 指令
  • 渠道特定指引
  • Bootstrap Project Context
  • Runtime 环境完整信息

minimal 模式（子代理）

  • 仅 4-5 个核心段落
  • 无 Skills / Memory / Messaging
  • 无 Heartbeats / Silent Replies
  • 无 Reactions / Voice / Docs
  • extraSystemPrompt 标题改为 "Subagent Context"
  • Token 占用降低 60-80%
注意

系统提示词是在每次 Agent Run 开始时完整重建的（包括 Compaction 流程中）。这意味着配置变更（如添加新工具、修改 bootstrap 文件）会在下一次运行时立即生效，无需重启 Gateway。
