调度全景：三层时间引擎

类比

把 Gateway 想象成一栋大厦的物业管理中心。Cron Service 是预设好的工作排班表（"每天 8 点浇花"）， Heartbeat 是安保人员每 30 分钟巡逻一次的时钟， APNs Push Wake 则是对讲机——当需要某个保安时，即使他在休息室也能被呼叫回来。

Cron 定时任务系统

OpenClaw 的 Cron 系统是一个完整的 in-process 定时任务引擎。它支持三种调度模式， 用户通过 YAML 配置或 Gateway API 创建任务后，系统会在指定时间自动触发 Agent 运行。

三种调度模式

模式schedule.kind配置示例行为
Cron 表达式 "cron" expr: "0 8 * * 1-5" 标准 5/6 字段 cron 表达式，通过 croner 库解析，支持时区 tz
固定间隔 "every" everyMs: 3600000 基于 anchorMs 锚点的等间隔触发，自动计算 nextRunAtMs
一次性 "at" at: "2026-03-14T09:00:00Z" 到达指定时间后执行一次，执行后自动禁用或删除

核心调度逻辑

TypeScript src/cron/schedule.ts 
// computeNextRunAtMs — 统一计算下次执行时间
export function computeNextRunAtMs(
  schedule: CronSchedule,
  nowMs: number
): number | undefined {
  if (schedule.kind === "at") {
    // 一次性任务：时间未过则返回，否则 undefined
    const atMs = parseAbsoluteTimeMs(sched.at);
    return atMs > nowMs ? atMs : undefined;
  }
  if (schedule.kind === "every") {
    // 固定间隔：基于 anchorMs 对齐
    const elapsed = nowMs - anchor;
    const steps = Math.ceil(elapsed / everyMs);
    return anchor + steps * everyMs;
  }
  // cron 表达式：委托 croner 库计算
  const cron = resolveCachedCron(expr, timezone);
  return cron.nextRun(new Date(nowMs))?.getTime();
}

Timer 驱动与安全机制

Cron Service 使用 单一 setTimeout 定时器（而非 setInterval）来驱动任务执行。 每次任务完成或配置变更后，系统会重新计算所有任务的 nextRunAtMs， 找到最近的触发时间并用 armTimer 设置下一个唤醒点。

安全边界

MIN_REFIRE_GAP_MS = 2,000ms：防止 computeJobNextRunAtMs 返回同秒时间导致无限重触发循环（Issue #17821）。

MAX_TIMER_DELAY_MS = 60,000ms：即使下个任务在 1 小时后，定时器也最多 sleep 60 秒后重新校准，确保配置热重载能及时生效。

Restart Catchup：Gateway 重启时扫描被中断的任务（runningAtMs 残留标记），清除后执行错过的任务。

每个 Cron 任务执行时生成独立的 session key：agent:{agentId}:cron:{jobId}:run:{runId}， 确保 Cron 任务之间、以及 Cron 与用户对话之间的会话上下文完全隔离。

Heartbeat 心跳机制

Heartbeat 是 OpenClaw 的 "自主巡检" 系统。与 Cron 不同的是，Heartbeat 不是用户定义的任务， 而是系统内置的 Agent 自检机制——定期让 Agent 审视自己的工作空间，发现变化后主动向用户推送消息。

运作原理

TypeScript src/infra/heartbeat-runner.ts 
// HeartbeatRunner — 多 Agent 心跳调度器
export function startHeartbeatRunner(opts) {
  // 1. 为每个配置了 heartbeat 的 Agent 创建状态
  const agents = resolveHeartbeatAgents(cfg);
  // 2. 计算各 Agent 的 intervalMs
  //    默认 DEFAULT_HEARTBEAT_EVERY = "30m"
  // 3. 单一 setTimeout 驱动，到期后触发 requestHeartbeatNow
  // 4. 运行时：
  //    - 检查 Main Lane 是否空闲（queueSize === 0）
  //    - 检查是否在 activeHours 范围内
  //    - 读取 HEARTBEAT.md 判断是否有内容
  //    - 调用 getReplyFromConfig 让 Agent 生成回复
  //    - 用 HEARTBEAT_TOKEN 判断是否需要真正投递
}

心跳决策流程

检查项条件结果
是否启用 areHeartbeatsEnabled() 返回 false 跳过，返回 skipped: disabled
活跃时间 不在 activeHours 范围内 跳过，返回 skipped: quiet-hours
主车道繁忙 getQueueSize(Main) > 0 跳过，返回 skipped: requests-in-flight
HEARTBEAT.md 空 文件存在但内容为空 跳过，返回 skipped: empty-heartbeat-file
Agent 回复为 HEARTBEAT_TOKEN "一切正常" 信号 可选发送 ok 确认，修剪转录记录
回复与上次相同 24h 内重复内容 去重跳过，防止 "唠叨" 行为
有实质内容 非 token、非重复 通过 deliverOutboundPayloads 投递到目标通道
设计洞察

Heartbeat 的精妙之处在于它的 "零噪声" 设计。Agent 每次心跳运行时都会读取 HEARTBEAT.md 并生成回复， 但只有当回复包含真正有价值的信息时（非 HEARTBEAT_TOKEN）才会向用户推送。 同时，ok 运行产生的转录记录会被 pruneHeartbeatTranscript() 剪除， 防止 "一切正常" 的空转对话历史膨胀。

Heartbeat 与 Cron 事件联动

Heartbeat 不仅是定时巡检，还充当 系统事件中继站。 当 Cron 任务执行完成或 exec 命令完成时，系统会写入 system event entry， Heartbeat 的 preflight 阶段会检测这些事件并构造专用 prompt：

调度与 Lane Queue 协作

调度系统产生的任务不会直接执行，而是通过 Lane Queue 进行并发控制。 每种调度任务使用独立的 Lane，确保不同类型的任务之间互不阻塞。

TypeScript src/process/lanes.ts + src/gateway/server-lanes.ts 
// 四条预定义车道
export const enum CommandLane {
  Main     = "main",      // 用户消息处理
  Cron     = "cron",      // Cron 定时任务
  Subagent = "subagent",  // 子 Agent 委托任务
  Nested   = "nested",    // 嵌套 Agent 调用
}

// Gateway 启动时设置各车道并发度
export function applyGatewayLaneConcurrency(cfg) {
  setCommandLaneConcurrency(CommandLane.Cron, cfg.cron?.maxConcurrentRuns ?? 1);
  setCommandLaneConcurrency(CommandLane.Main, resolveAgentMaxConcurrent(cfg));
  setCommandLaneConcurrency(CommandLane.Subagent, resolveSubagentMaxConcurrent(cfg));
}

Cron Lane（默认并发 1）

Cron 任务默认串行执行，防止多个定时任务同时操作共享资源。可通过 cron.maxConcurrentRuns 调大。

Main Lane（可配置并发）

用户消息走 Main Lane。Heartbeat 在执行前会检查 getQueueSize(Main) > 0，主动让路给用户请求。

Lane 切换规则

嵌套 Agent 不继承 Cron Lane。resolveNestedAgentLane() 明确规定：当父任务在 cron Lane 时， 子任务切换到 nested Lane，避免 Cron 任务的串行限制阻塞内部的 Agent 调用链。

Node Registry 多设备管理

OpenClaw 支持多个 "Node" 同时连接到同一个 Gateway。每个 Node 代表一个客户端设备—— 可以是 macOS 桌面应用、iOS 移动端、Android 客户端，甚至是另一台服务器上的 CLI。 NodeRegistry 负责管理这些设备的注册、能力发现和远程调用。

TypeScript src/gateway/node-registry.ts

远程调用机制

Gateway 可以通过 NodeRegistry.invoke() 向任意已连接的 Node 发送命令。 这是一个基于 WebSocket 的 RPC 机制：Gateway 发送 node.invoke.request 事件， Node 执行后返回 node.invoke.result。整个过程有超时保护（默认 30 秒）。

Node Remote Invoke 时序
Gateway                          Node (iOS/macOS)
   |                                  |
   |--- node.invoke.request --------->|
   |    { id, command, paramsJSON }   |
   |                                  |--- 执行命令
   |                                  |
   |<-- node.invoke.result -----------|
   |    { id, ok, payloadJSON }       |
   |                                  |
   |--- [超时 30s] ------------------>|
   |    resolve({ ok: false,          |
   |      code: "TIMEOUT" })          |

设备配对流程

新设备连接 Gateway 前需要经过 配对（Pairing） 流程。 OpenClaw 实现了基于 HMAC 签名的设备认证协议，支持 v2 和 v3 两个版本的认证载荷格式。

TypeScript src/gateway/device-auth.ts 
// V3 认证载荷格式（含平台和设备族信息）
export function buildDeviceAuthPayloadV3(params): string {
  return [
    "v3",                       // 版本标识
    params.deviceId,            // 设备 ID
    params.clientId,            // 客户端 ID
    params.clientMode,          // 连接模式
    params.role,                // 角色（viewer/editor/admin）
    params.scopes.join(","),    // 授权范围
    String(params.signedAtMs),  // 签名时间戳
    params.token ?? "",         // 认证 token
    params.nonce,               // 防重放 nonce
    platform,                   // darwin / ios / android
    deviceFamily,               // iPhone / Mac / Android
  ].join("|");
}

APNs 推送唤醒

当 Gateway 需要在某个 iOS/macOS Node 上执行命令，但该 Node 当前不在线时， 系统会通过 Apple Push Notification service (APNs) 发送静默推送来唤醒设备。

两种推送类型

类型函数APNs push-typepriority用途
Alert sendApnsAlert() alert 10（立即） 测试推送、用户可见通知
Background Wake sendApnsBackgroundWake() background 5（节能） 静默唤醒设备重连 Gateway
TypeScript src/infra/push-apns.ts 
// 静默推送唤醒 — content-available: 1 告诉 iOS 在后台唤醒 app
export async function sendApnsBackgroundWake(params) {
  const payload = {
    aps: {
      "content-available": 1,  // iOS 后台唤醒标志
    },
    openclaw: {
      kind: "node.wake",      // OpenClaw 自定义元数据
      reason: params.wakeReason ?? "node.invoke",
      nodeId: params.nodeId,
      ts: Date.now(),
    },
  };
  return await sendApnsPush({
    pushType: "background",    // APNs 静默推送类型
    priority: "5",             // 节能优先级
  });
}

唤醒后的重连等待

推送发出后，Gateway 并不立即放弃。它会进入一个 轮询等待 周期， 等待目标 Node 重新建立 WebSocket 连接：

TypeScript src/gateway/server-methods/nodes.ts 
export const NODE_WAKE_RECONNECT_WAIT_MS      = 3_000;   // 首次等待 3 秒
export const NODE_WAKE_RECONNECT_RETRY_WAIT_MS = 12_000;  // 重试等待 12 秒
export const NODE_WAKE_RECONNECT_POLL_MS       = 150;     // 每 150ms 轮询一次
const NODE_WAKE_THROTTLE_MS                    = 15_000;  // 同一 Node 15 秒内不重复唤醒

APNs JWT 认证

OpenClaw 使用 ES256 JWT token 与 APNs 通信，支持从环境变量或文件读取 .p8 私钥。 JWT 有 50 分钟缓存期（APNS_JWT_TTL_MS），避免频繁签名的开销。

环境变量用途
OPENCLAW_APNS_TEAM_IDApple Developer Team ID
OPENCLAW_APNS_KEY_IDAPNs Auth Key ID
OPENCLAW_APNS_PRIVATE_KEY_P8内联 .p8 私钥（或使用 _PATH 指定文件路径）
类比

APNs 推送唤醒就像酒店的 wake-up call 服务。客人（iOS 设备）退房休息后， 前台（Gateway）无法直接联系，但可以通过电话总机（Apple Push Service） 拨一个无声电话（content-available: 1），让客人自己走到前台报到（重新建立 WebSocket 连接）。
